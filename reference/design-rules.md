一份"照着做就不会难看"的规则表。每条都是实际做图标时踩出来的。

## 一、底板几何

### 用超椭圆，不要用圆角矩形

iOS / macOS 的图标圆角不是圆弧，而是**连续曲率**（曲率从直边到圆角连续变化），肉眼看比圆角矩形"更饱满"。

超椭圆 `|x/a|^n + |y/b|^n = 1` 是它的标准近似：

| n | 形状 | 等价圆角半径（占半边长） |
|---|---|---|
| 2 | 正圆 | 100% |
| 3 | 饱满圆角方块 | ~70% |
| **5** | **≈ iOS 连续圆角** | **~22%** |
| 9 | 接近直角 | ~6% |
| 直线 | 直角矩形 | 0 |

推导线（n=5）：45° 处的边界点到中心距离是 `a · 2^(-1/5) = 0.8706a`，
所以相对直边中点"内收" `0.1294a`；换成圆角矩形，等价的 `r` 满足 `r(1 - 1/√2) = 0.1294a`，
得 `r ≈ 0.442a`。半边长 `a` = 226（512 画布、内缩 30）时 `r ≈ 100`，
占全宽 452 的 **22.1%** —— 和 iOS 官方的 22.37% 基本一致。

### 留白

- 512 画布下内缩 **30**（≈6%）。这是本技能的默认值。
- 要"满幅"时用 `--tile rect --inset 0`（做 maskable / 需要底板铺满时）。

### 把点列变成贝塞尔：**必须用向心参数化**

`catmull_to_path()` 的公式（α = 0.5，即 `d = |Δp|^0.5`）：

```
d1 = |p1-p0|^0.5      d2 = |p2-p1|^0.5      d3 = |p3-p2|^0.5

c1 = ( d1²·p2 − d2²·p0 + (2d1² + 3d1d2 + d2²)·p1 ) / ( 3d1(d1+d2) )
c2 = ( d3²·p1 − d2²·p3 + (2d3² + 3d3d2 + d2²)·p2 ) / ( 3d3(d3+d2) )
```

**为什么不能用均匀参数化**（`c1 = p1 + (p2−p0)/6`）：当采样点间距不均匀时（手工取点、
RDP 简化后都会这样），均匀版本会在曲率突变处产生**自交小环**，渲染出来就是图案边缘的
洋红/白色细刺。改用向心参数化后彻底消失 —— 这是本项目实测到的。

### 采样密度

- 超椭圆：**32 个采样点**已经看不出折线（512 画布、2 位小数，路径约 1.2 KB）。
- **长直边要加密。** 一条被简化成两点的长直边，样条在两端切线影响下会向外鼓 1~3px。
  给直边中间补几个取点即可。

## 二、配色

### 渐变：只做同色相的明暗

```
offset 0.00  →  light   (H 不变, S × 0.99, L × 1.14 + 0.05)
offset 0.52  →  base    (你要的主色)
offset 1.00  →  dark    (H 不变, S × 1.02, L × 0.60)
```

方向固定为左上 → 右下（`x1=0,y1=0 → x2=1,y2=1`）。

- **不要跨色相**（比如紫→蓝）。一眼假。
- 中段锚在 **0.52** 而不是 0.5：让主色占据视觉中心偏上，主体图形落在主色上。
- 想完全自己控色就用 `--theme '{...}'`。

### 镂空细节色 = 该处底板的等效色

眼睛、嘴、叶脉这类"挖空"细节，如果填白或填黑，看起来都是**贴上去的**。
正确做法是取该点在底板渐变上的颜色：

```
把点投影到渐变对角线上 → t = ((x-x0)/w + (y-y0)/h) / 2
t ≤ 0.52 :  lerp(light, base, t/0.52)
t > 0.52 :  lerp(base, dark,  (t-0.52)/0.48)
```

`color_on_gradient()` 就是这个。每个图形在 `GLYPHS` 里声明一个 `cutout_at` 采样点即可。

## 三、细节尺度：按 512 设计，按 32 验收

缩放比 = `目标尺寸 / 512`。**32px 下缩放比是 1/16**。

| 在 512 里 | 在 32px 里 | 结论 |
|---|---|---|
| 8 单位 | 0.5 px | 看不见，别做 |
| 12 单位 | 0.75 px | 勉强，只在 64px 以上有意义 |
| **20 单位** | **1.25 px** | **32px 下可见的下限** |
| 30 单位 | 1.9 px | 舒服 |

推论：
- 笔画宽度 ≥ **12**，想在小尺寸还清楚就 ≥ **20**。
- 小圆点半径 ≥ **10**（直径 20）。
- 主体图形外接框约占画布 **60~75%**（本技能图形大致落在 `[96, 416]`）。

**验收方法**：出多尺寸预览图，缩到 16px 还能认出是什么，就算过。

```bash
python3 scripts/render_png.py --svg favicon.svg --sheet --sheet-out icon-sheet.png
```

## 四、怎么快速画出一个新图形

### 变体对比法（省时间的关键）

不要"改一版 → 刷新 → 再看"。一次定义 4 个变体，并排渲染成一张图：

```python
# 见本技能开发时用的写法：把变体写成 dict，逐个替换进 SVG，拼一张 HTML，截一张图
VARIANTS = {
    "A 当前":   "...贝塞尔路径 A...",
    "B 尾叶加厚": "...贝塞尔路径 B...",
    "C 更宽更钝": "...贝塞尔路径 C...",
    "D 对称":    "...贝塞尔路径 D...",
}
```

渲染一张对比图，一次就能选出最好的。**两轮定稿**，而不是二十轮。

### 描摹 vs 手绘

| | 描摹位图（marching squares + RDP + 样条拟合） | 手绘 |
|---|---|---|
| 产物体积 | 29 KB / 696 行路径 | **3.9 KB** |
| 保真度 | 再调也就 IoU 0.98~0.99 | — |
| 调整成本 | 极高（改一处要重跑整条管线） | 改几个控制点 |
| 亚像素问题 | 半格偏移、尖点自交、直边鼓包…… 无穷 | 基本没有 |

**除非用户明确要求还原某个已有图标，否则一律手绘。** 而且手绘出来的通常更好看。

## 五、渲染与校验环境

### 无头浏览器出图

```bash
CHROME="/Applications/Google Chrome.app/Contents/MacOS/Google Chrome"
"$CHROME" --headless --disable-gpu --no-proxy-server --hide-scrollbars \
  --force-device-scale-factor=1 --virtual-time-budget=2500 \
  --window-size=512,512 --screenshot=out.png file:///abs/path/page.html
```

- **透明底**：加 `--default-background-color=00000000`
- **视口**：`--window-size=W,H` 就是截图尺寸，别指望它保持 —— 换尺寸要重新设
- **代理**：本地/文件 URL 一定加 `--no-proxy-server`，否则 `HTTP_PROXY` 环境变量会让你拿到 502
- **慢渲染**：`--virtual-time-budget=2500` 给外部资源一点时间

### 像素级校验（可选，但很有用）

在洋红底（`#FF00FF`）上渲染，就能同时看清：
- 底板轮廓（洋红=透明区域）
- 图案轮廓（白色）
- 合成是否有缺口（洋红细缝 = 底板与图形没对齐）

```python
is_magenta = lambda p: p[0] > 200 and p[2] > 200 and p[1] < 80
```

IoU 参考：外框 ≥ 0.995、图形 ≥ 0.98 就算高度一致。
